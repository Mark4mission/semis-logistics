# Task 관리 — 설계 (2026-11-15, 구현 전)

> 공개 저장소 문서다. 사람 이름 · 연락처 · 실제 업무 자료는 적지 않는다(HANDOFF §6-4). 시험 · 예시의 이름은 지어낸 것만.
> Mark 가 "알아서 진행하고 검증까지 끝낸 뒤 알려 달라"고 해서 설계 질문 없이 정했다. `(내 판단)` = 설계자가 정한 것(Mark 확인 전 — 고칠 수 있게 까닭을 함께 적음). 표시 없는 것 = Mark 요청(11-15).

## 1. 왜

안전보안파트(파트장 + 파트원, 지금 2명)는 할 일을 각자 메모장 · 수첩에 적는다. 서로 무엇을 하고 있는지, 공문에서 생긴 기한이 누구 몫인지 파트 회의 때 말로 맞춘다.

- 각자의 할 일을 **쉽게 적고 함께 본다**. 마치면 **맨 앞 체크박스**를 눌러 목록에서 뺀다.
- 한두 줄 내용이 기본이고 **날짜 · 장소 · 담당자 · 관련 팀**을 쉽게 붙인다.
- **파트 회의 때** 이 화면 하나로 적고 · 고치고 · 지운다.
- **일정관리 · 아르고 · 접수 카운터**와 이어져 같은 일을 두 번 적지 않는다.
- 사용자는 50대 이상 — 단추 · 말이 적고, 색 · 아이콘이 알아서 갈라 준다.

## 2. 목표 · 비목표 · 안 되는 것

**목표**
1. 새 메뉴 **Task 관리**(홈 허브, 주소 `#/tasks`) — 안전보안파트(hq) · 시스템관리자가 할 일을 적고 함께 본다.
2. 줄마다 맨 앞 체크박스 → 마치면 목록에서 빠지고 '마친 일'로(되돌리기 · 다시 열기 가능).
3. 한 줄 빠른 입력 — 날짜 · 시각 말(내일 · 다음 주 수요일 · 11/20 · 오후 3시)을 알아듣고, 담당자 · 관련 팀 이름이 글에 있으면 칸을 채운다. 자세히 = 날짜 · 시각 · 장소 · 담당자(여러 명) · 관련 팀 · 중요 · 메모.
4. 색 · 아이콘 자동 구분 — 내용의 말로 분류(회의 · 교육 · 점검 · 보고 · 제출 · 장비 · 시설 · 기타)를 정해 아이콘 + 색, 기한 상태(지남 · 오늘 · 내일 · 이번 주)는 날짜 색, 담당자는 사람마다 색.
5. **회의 모드** — 사람별 칸에 그 사람의 할 일 · 칸마다 한 줄 입력 · 큰 글자 · 이번 주 마친 일. 인쇄하면 A4 회의 자료.
6. **일정관리**: 날짜가 있는 할 일이 달력에 칩으로 보이고(저장은 할 일 한 곳), 칩의 ○ 로 마침 표시.
7. **아르고**: 할 일을 읽고(이번 주 · 내 할 일 · 지난 것) · 추가 · 고치기 · 마침 · 지우기 — 모두 기존 확인 카드를 거친다.
8. **접수 카운터**: 공문에 제출 · 회신 기한이 있으면 '저장할 곳'에 **할 일** 줄이 **미리 켜져** 나오고, 사람이 '이대로 저장'을 눌러야 저장된다.
9. 홈 '오늘' 띠 한 칸(오늘 · 지난 할 일 수) · 통합 검색에서 할 일 찾기.

**비목표(이번 범위 밖 — 써 보고 필요하면 다음에)** `(내 판단)`
- 반복 할 일(매주 · 매월) — 일정관리 반복이 이미 있고, 할 일 반복은 '마치면 다음 회차 만들기' 규칙이 따로 필요하다.
- 하위 단계(체크리스트) · 댓글 · 첨부 올리기(접수 카운터가 붙인 원본 문서 연결만 있음).
- 미리 알림(푸시 · 메일) — 앱에 알림 길이 없다. 홈 '오늘' 띠 · 일정관리로 대신한다.
- 우선순위 여러 단계(Todoist p1~p4) — 별표(중요) 하나로 충분하다고 봄.
- 회의록과 묶기(회의 모드 결과를 회의록 결정사항으로 보내기).
- 파트 밖(화물팀 관리자 · 일반 직원)에게 보이기 · 맡기기.

**안 되는 것(돌아가도 실패)**
- 권한 밖 사람(manager 이하 · 협력업체 · 서명 세션)에게 할 일이 보이는 것 — 서버 권한표가 막아야 한다(화면만으로는 안 됨).
- 사람 확인 없이 할 일이 저장되는 것(아르고 바로 실행 설정은 기존 규칙 그대로 — 지우기 · 여러 건은 늘 확인).
- 두 사람이 회의 중 동시에 고칠 때 한쪽 변경이 사라지는 것 — 할 일 단위 병합이어야 한다.
- 검색 입력칸 · 빠른 입력칸에서 한글 조합이 자모로 풀리는 것(HANDOFF §6-11).

## 5. 데이터 — 공용 행 `tasks`

- 권한표 `key_acl ('tasks',3,3)` — 읽기 · 쓰기 모두 3(안전보안파트 · 시스템관리자). manager(2) · user(1) · 협력업체(서버 등급 늘 1) · 서명 세션(0)은 서버가 행을 주지 않는다(RLS). 화면은 로그인 때 읽을 권한이 없는 컬렉션을 기본값으로 비우므로 다른 모듈(일정관리 · 검색 · 홈 띠)도 빈 목록을 본다.
- 화면 쪽 사용 조건 `SemisTasks.canUse()` = `roleRank() >= 3` 이고 협력업체 · 서명 세션이 아님(화면의 협력업체 등급은 편집 허용 업체면 3 이 되므로 — 접수 카운터 `canW()` 와 같은 규칙). 메뉴 vis `hq` + 모듈 render 첫 줄 + 일정관리 · 검색 · 홈 띠 · 아르고 모두 이 조건.
- SYNC_KEYS 에 `tasks`, `freshData` 기본값 `tasks: []`, `normalizeData` 의 `rows` 표에 한 줄(id 없는 줄 버림) + 칸 정리는 `SemisTasks.norm`(아래). 맨 위 배열이라 대량 삭제 방어(`guardWipe` — 2건 이상 → 0건 차단)가 그대로 걸린다(한 건씩 지우므로 문제없음).
- 모양 = **할 일 배열**(일정 `schedules` 처럼 — id 배열이라 `merge3` 가 할 일 단위로 병합. 회의 중 두 사람이 다른 할 일을 고쳐도 둘 다 남는다):

```js
tasks: [{
  id: "tk_" + 무작위,        // 문자열 id(병합 · 아르고 되돌리기 diff 의 단위)
  t: "보안교육 자료 제출",     // 내용 1~2줄(300자, 줄바꿈 1개까지 — 화면은 2줄까지)
  memo: "",                  // 메모(2,000자)
  due: "2026-11-20",         // 날짜(기한) YYYY-MM-DD | ""
  time: "15:00",             // 시각 HH:MM | ""(날짜 없으면 비움)
  place: "",                 // 장소(100자)
  who: ["담당자 이름"],        // 담당자(여러 명, 이름 문자열 — 인원 관리 명단의 안전보안파트 사람을 고르거나 직접 적음)
  teams: ["수출파트"],        // 관련 팀(여러 개 — 인원 관리 그룹 + 직접 적음)
  cat: "",                   // "" = 자동 분류, 아니면 meet|edu|check|doc|equip|etc(직접 고름)
  star: false,               // 중요
  done: false, doneAt: "", doneBy: "",   // 마침(ISO 시각 · 이름)
  at: "ISO", by: "이름",      // 만든 때 · 사람
  upAt: "ISO", upBy: "이름",  // 마지막 고친 때 · 사람
  src: "",                   // "" 화면 | "desk" 접수 카운터 | "argo" 아르고
  file: { name, url }        // (접수 카운터만) 원본 사본 — tasks/ 폴더 표준 주소
}]
```

- 정규화(`normalizeData` rows 표에 한 줄 · `SemisTasks.norm`): id 없는 줄 버림 · 글자 길이 자름 · 날짜 · 시각 형식이 틀리면 비움 · who/teams 는 문자열 배열(중복 · 빈 값 제거, 각 8개) · cat 은 목록 밖이면 "". 멱등.
- 지우기 = 배열에서 빼기(서버가 모든 변경 직전 값을 90일 보관 — 시스템 설정 › 변경 이력에서 복원). `(내 판단)` 따로 휴지통을 두지 않는다.
- 마친 일은 지우지 않고 남긴다 — 1년 1,000건이어도 30만 자 안팎. `(내 판단)` 자동 정리는 두지 않는다(병합 · 되살아남 위험). 화면 '마친 일'은 최근 순 100건 + 더 보기.
- 파일: 접수 카운터가 붙이는 원본 사본은 새 폴더 `tasks/`(파일 함수 기본 등급 = 열람 3 · 올리기 3 — 권한표와 같아 **Edge `semis-logi-files` 변경 · 재배포 없음**).

## 6. 화면 — `js/tasks.js`(템플릿에서 시작) · `css/main.css` 한 구획

### 6-1. 머리말 · 구성(HANDOFF §6-29)

`[Task 관리 ⓘ] … [할 일 추가(주)][회의 모드(보조)][⋯][인쇄]`

- 주 단추 '할 일 추가' = 고치기 창(빈 칸). 보조 '회의 모드' ↔ '목록 보기'(같은 자리에서 바뀜).
- 블록 2개: ① 요약 띠(`ui.stats` — 할 일 · 오늘 · 지난 일 · 이번 주 마친 일) ② 목록 카드(빠른 입력 · 담당자 칩 · 탭 [할 일 n][마친 일] · 검색칸 · 목록).
- 담당자 칩(`.seg`): 전체 · 나 · 안전보안파트 사람들(인원 관리 명단에서 — 코드에 이름 없음) · 그 밖에 할 일에 적힌 사람. '나' = 로그인 계정 이름(`SeMIS.user.name` — 게터)과 같은 담당자. 만든 사람 · 고친 사람 · 마친 사람 칸도 이 이름.
- **전제(운영 확인 항목 §13-4)**: 파트원마다 계정이 따로 있고 계정 이름 = 인원 관리 이름(글자까지 같음). 어긋나면(계정 이름이 명단의 안전보안파트 사람이 아님 — 예: 여럿이 한 계정) '나' 칩을 숨기고 빠른 입력 담당 기본값을 비운다 — 엉뚱한 이름이 담당으로 쌓이지 않게. `(내 판단)` `(내 판단)` 처음 고른 칩은 '전체'(파트 공유가 목적) — 고른 칩은 계정별 navPrefs 에 기억.
- 약어 풀이 `GLOSS` 에 'Task' 한 줄(할 일 — 안전보안파트가 함께 보는 할 일 목록).

### 6-2. 빠른 입력

- 입력칸 하나(자리 글: `할 일을 적고 Enter — 예: 내일 오후 3시 보안교육 자료 제출`) + [추가] 단추. 칸 아래 한 줄 미리보기: 알아들은 날짜 · 시각 · 관련 팀 칩(아이콘 + 글자) + **담당 칩**(안전보안파트 사람마다 켜고 끄는 작은 단추 `aria-pressed` — 그 자리에서 바로 바꿈, 고치기 창을 열 필요 없음).
- 담당 기본값(누가 켜져 있나) = 글 속 이름 > 위 담당자 칩에서 고른 사람 > 나(내가 명단의 안전보안파트 사람일 때) > 비움. 사람이 미리보기 담당 칩을 누르면 그때부터는 누른 대로(다음 추가 뒤 기본값으로 돌아감). `(내 판단)` — 담당을 비워 두면 '누구 몫인지'가 회의 때 다시 문제가 되고, 파트장이 파트원 몫을 적을 때는 한 번 눌러 바꾼다.
- Enter · [추가] → 바로 저장(사람이 직접 친 글 = 확인한 것). 빈 글은 무시.
- 입력칸은 다시 만들지 않는다 — 목록만 `ui.repaintKeep`, 추가 뒤 칸을 비우고 포커스 유지.
- **알아듣는 말**(`SemisTasks.parse(text, { today, names, teams })` — 순수 함수, 시험):
  - 날짜: 오늘 · 내일 · 모레 · 글피 / (이번 주 · 이번주 · 금주) + 요일 / (다음 주 · 다음주 · 차주) + 요일(요일 없으면 다음 주 월요일) / 요일만(오늘 포함 가장 가까운 그 요일) / `11/20` · `11.20` · `11월 20일` · `2026-11-20` · `2026.11.20`(연도 없으면 올해 — 30일 넘게 지났으면 내년).
  - 알아듣지 않는 것 `(내 판단)`: 날만(`20일` — 공문의 '20일 이내 회신' 같은 기간과 헷갈림) · 월말(정기 '월말 보고'의 이름일 때가 많음) · `M.D` 꼴이 30일 넘게 지난 날(소수 '4.5' 와 헷갈림 — `/` · `월 일` 꼴만 내년으로 넘김) · 이번 주/다음 주 뒤 홀로 쓴 '일'('일요일'만). 반복 말(매주 · 매월 · 매일 · 격주 · 매년)이 낱말로 있으면 날짜 · 시각을 하나도 알아듣지 않고 글을 그대로 둔다.
  - 시각만 있고 날짜가 없으면 날짜 = 오늘(Todoist 와 같음 — 미리보기에 '오늘 15:00'으로 보임).
  - 날짜 뒤 '까지' · '에'는 함께 뺀다('내일까지 보고서 제출' → '보고서 제출'). 날짜 뒤 '부터'는 시작일이라 빼지 않는다(기한은 '까지' 쪽). 시각 뒤 '부터'는 할 일의 시작 시각이라 함께 뺀다('오후 2시부터 교육' → 오늘 14:00 '교육').
  - 시각: `오전|오후` + `N시`( `M분` | ` 반`) · `HH:MM` · `N시`만(1~6시는 오후로 — 업무 시간 `(내 판단)`).
  - 알아들은 날짜 · 시각 말은 내용에서 뺀다(남는 글이 없으면 원문 그대로 — 일주일 뒤 '내일'이 남아 헷갈리지 않게, Todoist 와 같음). 담당자 · 관련 팀 이름은 내용에 남겨 두고 칸만 채운다.
  - 담당자 = 안전보안파트 사람 이름(인원 관리) 중 글에 그대로 있는 이름. 관련 팀 = 인원 관리 그룹 이름(파트 · 협력업체 소속) 중 글에 있는 것.

### 6-3. 목록(할 일 탭)

- 묶음: **지난 일**(빨강) · **오늘**(주황) · **내일** · **이번 주**(월~일, 이번 주 남은 날) · **그 뒤** · **날짜 없음**. 빈 묶음은 숨김. 묶음 안 순서 = 중요 → 날짜 → 시각 → 만든 순.
- 줄: `[체크박스 28px] [분류 아이콘(색)] 내용(2줄까지)` / 둘째 줄 = 날짜 칩(상태 색 — '3일 지남' · '오늘 15:00' · '내일' · '11-20(목)') · 장소 · 담당자 칩(사람 색 · 이름) · 관련 팀 칩 · 메모 있음 · 별표 · 출처('접수' — 원본 보기). 
- 체크 → 마침(`done`, `doneAt` · `doneBy`) → 줄이 빠짐 + 알림 '마쳤습니다 · 되돌리기'(`toast(msg, false, { label: "되돌리기", run })` — 7초). 내용은 `<button>`(키보드 · 화면 읽기 프로그램은 이 단추로 고치기 창 — HANDOFF §6-29 ⑥). 줄의 나머지(체크박스 밖)를 누르는 것은 마우스 편의로만 같은 창(줄 상자에는 `role` · `tabindex` 를 주지 않음 — 일정관리 `wireInsp` 와 같은 방식). 체크박스는 진짜 `<input type="checkbox">` + `aria-labelledby`(내용 단추) — 접근성 이름 = 내용(WCAG 2.5.3).
- 마친 일 탭: 마친 날 기준 묶음(오늘 · 이번 주 · 그 전), 줄 체크박스는 켜진 채 — 끄면 다시 할 일로. 최근 100건 + 더 보기.
- 검색칸(`ui.search` · `searchValue` · `repaintKeep`): 내용 · 메모 · 장소 · 담당 · 관련 팀에서 낱말 모두 포함. 두 탭 공통.
- 빈 화면: '할 일이 없습니다.'(빈 화면 첫 등록 단추 예외 — 주 단추가 이미 있어 넣지 않음).

### 6-4. 고치기 창(`openModal`)

- 칸: 내용(2줄 글상자) · 날짜(달력 칸) + 빠른 칩 [오늘][내일][이번 주 금][다음 주 월][지움] · 시각 · 장소(최근에 쓴 장소 datalist — 할 일에서 모음, 코드에 값 없음) · 담당자(사람 칩 켜고 끄기 + 직접 적기) · 관련 팀(그룹 칩 + 직접 적기) · 분류(자동(지금 판정 표시) · 회의 · 교육 · 점검 · 수검 · 보고 · 제출 · 장비 · 시설 · 기타) · 중요(별) · 메모 · 출처(접수 카운터 원본 — 누르면 첨부 뷰어).
- 하단 `.modal-actions`(§6-10): [지우기](위험 · 고칠 때만 · 확인 창) [마침/다시 열기] [취소] [저장(주)].

### 6-5. 회의 모드

- 같은 카드 안에서 목록 대신 **사람별 칸**: 안전보안파트 사람 + 할 일에 적힌 그 밖 담당자 + '담당 없음'(할 일이 있을 때만). PC(1024 이상) 2~3칸, 모바일은 아래로 쌓음.
- 칸 머리 = 사람 색 동그라미 · 이름 · 남은 수. 칸 안 = 그 사람 할 일(여러 담당이면 각 칸에 — '함께: 이름'), 줄 = 큰 체크박스(32px) · 내용(16px 이상 — rem) · 날짜 칩. 줄을 누르면 고치기 창(같은 창).
- 칸 맨 아래 한 줄 입력: `+ 이름 할 일` — Enter 로 그 사람 담당 추가(날짜 말 알아들음). 입력칸은 다시 만들지 않는다(칸 목록만 바꿈).
- 칸 아래 접힌 '이번 주 마친 일 n'(펼치면 체크된 줄 — 끄면 다시 할 일).
- 인쇄(코어 A4) = 사람별 할 일 + 이번 주 마친 일(회의 자료). 인쇄 머리에 날짜.

### 6-6. 색 · 아이콘 자동 구분 `(내 판단)`

분류는 내용 · 메모의 말로 정한다(`SemisTasks.catOf` — 순서대로 먼저 맞는 것, 직접 고른 `cat` 이 있으면 그것). 색은 일정관리 12색 중에서 접수 카운터가 일정에 쓰는 뜻과 맞춘다(회의 파랑 · 교육 초록 · 점검 · 심사 빨강 · 규정 · 절차 갈색 · 행사 회색).

| 분류 | 말(예) | 아이콘 · 색 |
|---|---|---|
| equip 장비 · 시설 | 장비 · 검색기 · 엑스레이 · X-ray · ETD · CCTV · 수리 · 고장 · 교체 · 설치 · 시설 | 공구 · 청록 |
| check 점검 · 수검 | 점검 · 수검 · 심사 · 감사 · 평가 · 순찰 · 인증 · AEO · TSA · ACC3 | 체크 목록 · 빨강 |
| edu 교육 | 교육 · 훈련 · 이수 · 강의 · 연수 · 전파 · 세미나 | 학사모 · 초록 |
| meet 회의 | 회의 · 미팅 · 간담회 · 협의 · 면담 · 보고회 | 사람들 · 파랑 |
| doc 보고 · 제출 | 보고 · 제출 · 회신 · 공문 · 작성 · 서류 · 결재 · 기안 · 계획서 | 문서 · 갈색 |
| etc 기타 | (그 밖) | 점 · 회색 |

- 겹칠 때는 **업무 분야(장비 · 점검 · 교육 · 회의)를 동작(보고 · 제출)보다 먼저** 본다: '보안교육 자료 제출' → 교육 · '점검 결과 보고서 제출' → 점검 · '월간 보고서 제출' → 보고 · 제출. `(내 판단)` — 이 파트의 일은 대부분 제출 · 보고 · 작성으로 끝나므로 동작을 먼저 보면 거의 모두 갈색이 되어 색 구분이 사라진다. 기한이 급한지는 날짜 칩 색이 따로 알려 준다. 틀리면 고치기 창 '분류'에서 한 번 바꾸면 그 할 일은 그 분류로 고정.
- 기한 상태 색은 날짜 칩에만(지남 빨강 · 오늘 주황 · 내일 · 이번 주 진한 글자 · 그 뒤 · 없음 회색). 줄 왼쪽에 지난 일만 빨간 세로 띠.
- 사람 색: 이름 → 해시로 6색 중 하나(인원 관리 명단 순서와 무관 — 사람이 늘어도 같은 사람은 같은 색). 색만으로 구분하지 않고 이름 글자를 늘 함께(색맹).

## 7. 일정관리 연결(`js/calendar.js`)

- 날짜가 있는 할 일(마친 일 포함 — 흐리게)을 달력에 **읽기 전용 칩**으로 그린다. 일정 데이터에는 저장하지 않는다(할 일 한 곳만 고침 — 두 번 적지 않기). 기존 '다른 모듈 항목' 길을 쓴다: `calendar.js` `INSP_SRC`(지금 `inspection` · `learn`)에 `["tasks", () => window.SemisTasks]` 한 줄, `SemisTasks.calItems(from, to)` 가 항목 `{ ik: "tk:"+id, start: due, end: due, title: "[할 일] "+내용, color(분류 색 id), done, late(지남), sub(시각 · 장소 · 담당), go: [{ lb: "Task 관리에서 열기", ico, run }], chk, mark(want) }` 을 돌려준다. 메뉴가 보이고 모듈이 등록됐을 때만 부르는 기존 조건(`modCan`)이 그대로 권한을 거른다.
- 칩의 ○/✓ 로 마침 · 다시 열기(점검 일정 완료 체크와 같은 모양 · `mark(true|false)`) — 쓰기 권한(3) 있을 때만. 지금 `inspToggle` 의 알림 글이 보안 기록부 문구로 고정돼 있으므로 항목이 켤 때 · 끌 때 알림 글을 줄 수 있게(`chkMsg: { on, off }` — 없으면 지금 문구) 한 곳만 고친다.
- 다른 모듈 항목은 종일로 그려지므로(시각 없음) 시각은 `sub` 에 둔다. 일정관리의 담당 거르기를 켜면 다른 모듈 항목이 숨는 지금 규칙(교육 · 점검과 같음)을 그대로 따른다 `(내 판단 — 일정 담당과 할 일 담당은 이름 모양이 달라 섞지 않음)`.
- 칩 상세의 'Task 관리에서 열기' → 모듈 상태에 그 할 일 id 를 두고 `#/tasks` 로(검색 `pick` 과 같은 길) → 고치기 창.
- 일정관리는 manager(2) 도 보지만, 할 일은 3등급만 받고 `modCan` 도 막으므로 manager 화면에는 없다.
- 색 id 는 `SemisCalendar.COLORS` 의 이름(red · orange · yellow · green · teal · sky · blue · purple · pink · rose · brown · gray)만 쓴다(16진 색 금지).

## 8. 아르고 연결

- 읽기: `js/argo.js` `COLS.tasks = { mod: "tasks", label: "Task 관리", rows }` — 줄 = { id, title, due, time, place, who, teams, cat(분류 이름), star, done, doneAt(날짜만), memo(200자), src } · 순서 = 할 일 먼저(날짜 순) → 마친 일(최근 순). `argos_records` 의 from/to 가 '이번 주'에 맞게 날짜 칸은 due · doneAt 만 둔다(만든 때 at 은 빼서 '이번 주에 만든 다음 달 일'이 섞이지 않게).
- Edge `COLLECTIONS` 에 `["tasks", 3, "Task 관리 — 안전보안파트 할 일(done 이면 마친 일 · due 기한 · who 담당 · teams 관련 팀)"]`.
- 쓰기 도구 4개(일정 도구 4개와 같은 짝 — 모두 min 3, 확인 카드):
  - `task_add` { items[1~10]{ t, due, time, place, who[], teams[], memo, star } } — 2건 이상이면 바로 실행이어도 확인.
  - `task_update` { id, …바꿀 칸 } — 바뀐 칸 줄.
  - `task_done` { id, done }.
  - `task_delete` { id } — `danger` · 늘 확인.
  - 결과 카드 [Task 관리에서 보기] · 되돌리기(`keys: ["tasks"]`), 기록 `src: "argo"`.
- Edge 지침(쓰기 묶음 한 줄): 할 일은 task_* — 날짜는 [지금] 기준 YYYY-MM-DD, 담당 · 관련 팀은 사용자가 말한 이름 그대로, 일정(시간이 정해진 모임)과 할 일(누가 해야 할 일)을 헷갈리면 묻기.
- 보던 화면 제안 `CTX.tasks = ["tell", 0, "이번 주 할 일 정리해줘"]`.
- 안내 지식 `docs/ARGO-GUIDE.md` 메뉴 표에 한 줄 + 쓰기 기능 줄 + §6 용어 풀이에 'Task'(화면 `GLOSS` 와 같은 뜻 — HANDOFF §6-28) → `npm run argo:guide` → Edge 재배포(운영 적용 §13).
- **모델 · 생각 깊이(effort)는 바꾸지 않는다**(Edge `AI_MODELS` · `MAX_TOKENS` · payload 그대로 — 시험 AR13 이 문자열 확인).

## 9. 접수 카운터 연결(`js/desk.js`) — 사람 확인 뒤에만

- 새 저장할 곳 `KINDS.task = { label: "할 일", save: "Task 관리에 할 일로 저장", folder: "tasks", route: "tasks" }`(다른 줄의 '…에 저장' 말투와 같게).
- 사본 폴더 `folderFor(a)`(지금 `event` 만 '원본 첨부'를 끄면 `""`)에 `a.k === "task" && !a.file ? ""` 를 더한다 — 안 그러면 원본 첨부를 꺼도 `tasks/` 사본이 생기고 붙는다(`apply` 가 폴더마다 사본 · `fileArr` 가 폴더로 붙임).
- **미리 켜는 규칙**(`plan()` — 화면만, Edge 판독 지침 · `clean()` 변경 없음 `(내 판단)`): 판독 결과 `events[]` 중 `cat === "deadline"`(판독 지침이 '제출 · 회신 기한'을 여기에 넣음 — 전파 통보의 회신 기한 포함)마다 할 일 줄 하나를 **켜서** 만든다. 내용 = 기한 제목(문서 제목과 다르면 '기한 제목 — 문서 제목', 300자), 날짜 = 기한, 시각 · 장소 = 그 일정 값, 담당 = 분야별 담당(일정 줄과 같은 규칙), 관련 팀 = 판독의 기관 이름이 인원 관리 그룹과 같을 때만, 메모 = 판독 요약.
  - 같은 기한의 **일정 줄은 꺼서** 만든다(지금은 켬) — 할 일이 일정관리에 칩으로 이미 보이므로 켜 두면 달력에 같은 기한이 두 번 뜬다. 사람이 일정 줄을 켜면 둘 다 저장(막지 않음). `(내 판단)` 시험 DK04 기대값을 바꾼다.
  - 할 일 줄은 그 기한 일정 줄 **바로 뒤**에 둔다(사람이 둘을 나란히 보고 고르게).
  - 기한 일정이 없는 문서는 할 일 줄을 만들지 않는다 — '저장할 곳 추가'(지금 일정 · 이수 기록 · 문서함 단추 3개)에 네 번째 **할 일** 단추가 생겨 사람이 붙인다(빈 줄 = 켜짐, 칸 펼침 — 내용 처음 값 = 문서 제목).
  - 손댈 곳 전부: `KINDS` · `folderFor` · `plan` · `check` · `actBody` · `rowSub` · '저장할 곳 추가' 단추와 그 처리 · `commit`. 계획 배열이 바뀌므로 [DK] 묶음 전체를 돌려 기대값을 맞춘다.
- 줄 칸(고치기): 내용 · 날짜 · 시각 · 장소 · 담당 · 관련 팀 · 메모 · 원본 첨부(체크 — 켜면 tasks/ 사본). 검사: 내용 필수 · 날짜 · 시각 형식.
- 저장(`commit`): `SeMIS.data.tasks.push(할 일)` (`src: "desk"`, `file` = 사본) → 기록 `{ k: "task", label: "할 일 · 11-20 내용", route: "tasks" }`. 한 문장 확인의 'n곳' 셈에 들어간다. 직원 '내가 올린 문서'에는 저장한 화면 이름 '할 일'만 보인다.
- 저장 버튼 위계 · 3단계 띠 · '보관만 하기'는 그대로. **확인 없이 할 일을 쓰는 길은 없다**(사람이 '이대로 저장'을 눌러야 `commit`).

## 10. 홈 '오늘' 띠 · 검색 · 메뉴

- 홈 대시보드 '오늘' 한 줄 띠(`js/modules.js` `todayHTML()` — 등록 API 가 없어 교육 전파 `td-ln` 처럼 한 덩어리 추가)에 칸 `td-tk` '할 일' — `menuOk("tasks", "SemisTasks")` 일 때 `SemisTasks.todayData()` → `오늘 n · 지난 n`(지난 일이 있으면 경고 색), 남은 할 일이 하나도 없으면 칸을 그리지 않음. 누르면 `#/tasks`.
- 통합 검색 프로바이더 `tasks`(`group: "Task 관리"`, `module: "tasks"` — 메뉴 권한이 곧 검색 권한, `minRank: 3`, 결과 종류 꼬리표 `KIND_OF` 에 'Task 관리' → '할 일' 한 줄): 할 일(마친 일은 아래 줄에 '마침') — 제목 = 내용, 아래 줄 = 날짜 · 담당, 찾는 글 = 메모 · 장소 · 관련 팀. `pick` 이 모듈 상태에 그 할 일 id 를 두고(이미 그 화면이면 다시 그림 — 수검 화면 관례) 고치기 창을 연다. `js/tasks.js` 는 index.html 에서 search.js 뒤에 둔다.
- 메뉴: `defaultMenus()` 홈 허브 일정관리 다음에 `m("tasks", "Task 관리", <아이콘>, "tasks", "hq", "hub-home")`(운영 데이터에 없으면 `ensureSeedMenus` 가 넣음 — 메뉴 아이콘 칸은 다른 메뉴와 같은 방식). 패널 배지 = 오늘 + 지난 할 일 수(0 이면 숨김). 홈 허브 메뉴 수가 늘어 시험 D02 기대값(5/5 → 6/6)이 바뀐다 · H05(홈 허브 첫 메뉴 = 일정관리) 그대로.
- 특정 할 일 열기(검색 · 일정관리 · 접수 카운터 기록 · 아르고 결과 카드 공통): 주소는 모듈 id 그대로(`#/tasks` — 앱은 `tasks/<id>` 꼴을 풀지 않음) + `SemisTasks.open(id)` 가 모듈 상태에 id 를 두고 이동 · 렌더 뒤 고치기 창. 접수 카운터 기록의 단추는 지금처럼 `route: "tasks"`(목록으로) — 그 기록에서 바로 그 할 일을 여는 것은 하지 않는다 `(내 판단 — 기록 모양을 바꾸지 않음)`.

## 11. 보안 · 개인정보
